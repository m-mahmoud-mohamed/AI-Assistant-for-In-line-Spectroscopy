# Cut Tokens, Verify Locally, Keep Retrieval Simple

For a 60-page curated corpus with image-only slides, the state-of-the-art (2024–2026) architecture is a deterministic, checkpointed pipeline: a rule engine owns the decision status, a hand-built typed graph with verbatim evidence cards supplies the grounding, and the LLM is confined to typed extraction and short constrained prose that cites card IDs while code injects and checks the quotes. The first-hand the development endpoint measurements show that the current 72-second run is a decode-length problem, not a retrieval or first-token problem. Time to first token is **0.12–0.16 s on all four models**, yet the draft and repair calls (median ~2,180 output tokens each) consumed **60.3 of 72.2 s**, and the Gemma 4 31B critic is the slowest model measured (55 tok/s). Cutting LLM output to what code cannot write, splitting the draft into parallel section calls (measured **2.5x** aggregate speed-up at ~280 tok/s), replacing whole-report repair with sentence-level patches, and moving support-checking to a small local model projects to roughly **8–18 s per assessment** (estimate, not yet measured end to end) at 4–6 requests instead of 4. The binding quota is the **1,000/day and 3,000/month** cap, not 30/min, so every avoided request matters. Retrieval upgrades (rerankers, GraphRAG, ColPali) have no evidence of paying off at this scale, whereas verification has the most headroom: the 0.649 claim-support score comes from a single generic LLM critic and is partly a judge artifact until measured against expert labels. No published study evaluates an LLM assistant for PAT feasibility scoping, so every figure for this exact combination below is a projection from adjacent results and must be confirmed on the project's own evaluation set.

## Decode length, not first-token delay, consumed the 72 seconds

Today's streaming measurements on the development endpoint endpoint (thinking off, ~450–550 output tokens of prose) change the latency picture that public benchmarks suggest. Artificial Analysis lists Qwen3.5-397B non-reasoning at 56 tok/s with 2.23 s time to first token, or 11.17 s for a 500-token reply ([Artificial Analysis](https://artificialanalysis.ai/models/comparisons/qwen3-5-397b-a17b-non-reasoning-vs-qwen3-5-397b-a17b)); the development endpoint delivers the same reply in about 4.5 s, roughly 2.5x faster, and sits near the top of the published provider range of 13–141 tok/s ([Artificial Analysis providers](https://artificialanalysis.ai/models/qwen3-5-397b-a17b-non-reasoning/providers)).

| Measurement (the development endpoint, 2026-10-17) | TTFT | Decode speed | Derived |
|---|---|---|---|
| Qwen3.5-397B-A17B | 0.16 s | 114 tok/s | 500-token reply in 4.5 s |
| DeepSeek V4 Flash | 0.12 s | 142 tok/s | 500-token reply in 3.6 s |
| Gemma 4 31B | 0.14 s | 55 tok/s | 500-token reply in 9.2 s |
| Qwen3-30B-A3B-Instruct-2507 | 0.15 s | 219 tok/s | 500-token reply in 2.4 s |
| 4 parallel Qwen3.5-397B calls | n/a | 74–95 tok/s each | ~1,880 tokens in 6.7 s wall (~280 tok/s aggregate); sequential equivalent ~16.7 s |
| JSON schema vs json_object (Qwen3.5-397B) | n/a | 94.5 vs 95.3 tok/s | 0.8% difference, no measurable schema overhead |

Because first-token delay is negligible, techniques that attack prefill do nothing for this pipeline. OpenAI's latency guidance states the same asymmetry: halving output tokens roughly halves latency, while halving input tokens improves it by only 1–5% ([OpenAI](https://developers.openai.com/api/docs/guides/latency-optimization)). Prefix caching is therefore a non-lever, and on the Qwen3.5 hybrid architecture it is also unreliable: vLLM reports a prefix-cache hit rate of 0–0.1% on Qwen3.5-35B-A3B and block-granular caching that gives 0% hits on a 479-token prompt ([vLLM issue 36493](https://github.com/vllm-project/vllm/issues/36493), [vLLM issue 40696](https://github.com/vllm-project/vllm/issues/40696)). Model size also fails to predict speed: the 3B-active Qwen3-30B model decodes **1.9x** faster than the 17B-active 397B model, while the 31B dense-class Gemma runs at half the 397B's rate. The current critic call (7.7 s) therefore runs on the slowest endpoint available, probably emitting ~400 tokens (inference from 7.7 s at 55 tok/s).

The stored 72-second run decomposes cleanly, and the right-hand column is a projection built from the measured rates above rather than a measurement.

| Stage | Stored run | Share | Proposed (estimate) | Basis |
|---|---|---|---|---|
| Deterministic engine, retrieval | <0.1 s | ~0% | <0.1 s, paints scaffold and headline status | already measured |
| Extraction | 4.2 s | 6% | 2.2–4.2 s | ~450 tokens at 219 vs 114 tok/s; keep 397B until parity is shown |
| Draft | 24.2 s | 34% | 4.6–8.2 s | 3 parallel section calls, 400–730 tokens each at ~90 tok/s |
| Verification | 7.7 s | 11% | <1 s local, plus 0–2 s grey-band call | small checker, unbenchmarked |
| Repair | 36.1 s | 50% | 0 s if clean, 1.5–3 s patching flagged sentences | sentence-level patches in parallel |
| Total | 72.2 s | 100% | about 8–18 s | first LLM prose at ~2.4–4.4 s |

Four levers explain the projected gain, in order of size. First, repair is the largest single item and is a near-duplicate of the draft: regenerating the whole report re-rolls sentences that already passed, whereas patching only flagged units bounds the cost (section 4). A runaway call reaching the 12,000-token cap would run ~105 s at 114 tok/s, so per-section `max_tokens` of about twice the expected length is a latency guarantee as much as a safety net. Second, fewer output tokens: identifiers, units, citation keys, rule verdicts, and any sentence that merely restates engine output should be written by code, and compact schemas with evidence fields ordered before conclusion fields keep structure cheap. The measured schema-versus-json_object parity compares two constrained modes, so it shows that a schema adds nothing beyond generic JSON grammar rather than proving zero overhead against free text; the XGrammar paper's 6.2 versus 6.3 ms per token supports the low-overhead reading ([XGrammar](https://arxiv.org/html/2411.15100v3)). Field ordering matters because later evidence shows that most "JSON-mode reasoning loss" comes from format-requesting prompts and answer-before-reasoning order rather than the grammar mask ([Format Tax](https://arxiv.org/abs/2604.03616), [Tam et al.](https://arxiv.org/html/2408.02442v1)).

Third, parallel section generation follows Skeleton-of-Thought, which reports up to 2.39x speed-up but warns that it "currently ignores the dependencies between points" and costs coherence ([SoT](https://arxiv.org/html/2307.15337v3)). A deterministic skeleton removes SoT's skeleton-generation stage, and the measured four-way run is almost exactly draft-sized: ~1,880 tokens in 6.7 s versus 2,180 tokens in 24.2 s for the stored single-call draft. Per-stream speed falls 17–35% under four-way load, so returns diminish: for a 1,200-token draft the estimates are ~10.7 s for one call, 6.2 s for two, 4.6 s for three and 3.7 s for four, and the fourth call buys under a second. Coherence risk is controlled by giving every section call the same report state, generating the headline from the engine's decision status instead of an LLM summary, and running a deterministic cross-section check after merge. Fourth, keep thinking off everywhere: the reasoning variant of Qwen3.5-397B needs ~60 s to the first answer token versus 2.2 s non-reasoning ([Artificial Analysis](https://artificialanalysis.ai/models/comparisons/qwen3-5-397b-a17b-non-reasoning-vs-qwen3-5-397b-a17b)), and the toggle is `chat_template_kwargs.enable_thinking=false` ([Qwen3.5 model card](https://huggingface.co/Qwen/Qwen3.5-397B-A17B)). The stored run's ~90 tok/s effective draft rate is consistent with thinking being off, but that should be confirmed from usage counters.

Static task-to-model routing is a fifth, riskier lever. Extraction and verbalising deterministic facts could move to Qwen3-30B-A3B (219 tok/s), but backbone sensitivity in the closest spectroscopy-agent paper is severe (Corn R2 0.925 with one backbone and 0.673 with another; milk classification 96.1% versus 50.8%) ([LUMIR](https://arxiv.org/pdf/2507.21471)), so each routed stage needs an equivalence test on the gold set. Per-query routers such as RouteLLM optimize cost on chat benchmarks and add a step, so they do not fit a pipeline whose stages are known. Server-side speculative decoding (MTP gives +100–159% at batch 1 on a tuned Qwen3.5 stack ([TokenSpeed](https://pytorch.org/blog/up-to-580tps-new-speed-record-of-qwen3-5-397b-a17b-on-gpu-for-agentic-workloads-with-tokenspeed/))) is not client-controllable; the 4-way test shows the server has headroom, so asking the development endpoint is a low-priority courtesy rather than a dependency.

The rate-limit headers resolve a conflict in the background notes, where the development endpoint's documentation showed example limits of 10/min, 200/h, 400/day and 3,000/month: the real limits are **30/min, 200/h, 1,000/day, 3,000/month**. With c requests per report, the monthly cap allows 3,000/c reports: 750 at the current 4 calls, 600 at 5, 500 at 6, 375 at 8. One 20-case evaluation pass at ~5 calls costs ~100 requests, so about 30 passes would exhaust a month with nothing left for demos. The per-minute cap is irrelevant below roughly five simultaneous reports. Two consequences follow. The LLM critic is 1 of 4 current requests (25% of quota), so a local checker saves requests as well as seconds. And evaluation must run on recorded fixtures (cache each LLM output by prompt hash) so deterministic stages can be regression-tested for free. Whether one `/completions` request with a list of prompts counts once is unverified and testable by reading headers before and after, but it bypasses chat templates and streaming per section, so it is a fallback, not a plan.

## At 200 evidence cards, the typed graph beats every added retrieval layer

The retrieval literature's headline numbers come from corpora one to three orders of magnitude larger than this one, so they bound the upside rather than predict it. Contextual embeddings plus contextual BM25 plus reranking cut top-20 retrieval failures from 5.7% to 1.9% in Anthropic's tests, but the same post says a knowledge base under 200,000 tokens (about 500 pages) can simply sit in the prompt ([Anthropic](https://www.anthropic.com/news/contextual-retrieval)). Adding BM25 to dense retrieval lifted nDCG@10 by only 2.3 points on TREC DL19 ([Wang et al.](https://arxiv.org/html/2407.01219)). At 70–200 cards a top-20 cut covers about 10% of the pool, so first-stage recall is near ceiling and a reranker (Qwen3-Reranker-4B costs about 1.2 s for 50 pairs per one secondary report ([presenc.ai](https://presenc.ai/research/best-open-weight-reranker-models-2026))) mainly improves ordering. The existing graph-first plus BM25 plus Qwen3-Embedding-4B RRF is already the recommended hybrid; the free upgrade is a deterministic contextual header (document, section, technique, application, scope label) prepended to each card before indexing, which reproduces contextual retrieval without LLM calls. A reranker is a test against gold card IDs, not a build item.

LLM-built graph methods fail the cost-benefit test and carry a specific risk for a system that must say "not in the corpus". HippoRAG 2 is the only variant with consistent gains (average F1 59.8 versus 57.0 for dense retrieval), while GraphRAG scored 49.6 and indexing consumed 115.5M input tokens against 9.2M for HippoRAG 2 on an 11,656-passage corpus ([HippoRAG 2](https://arxiv.org/html/2502.14802v2)). LLM-extracted graphs contained only 65.8% of answer entities, and on questions with no answer in the corpus GraphRAG's community-global mode abstained correctly 19.27% of the time versus 96.01% for plain RAG ([Han et al.](https://arxiv.org/html/2502.11371v3)). On fact lookups plain RAG ties graph methods ([GraphRAG-Bench](https://arxiv.org/html/2506.05690)). The one directly relevant experiment, small and single-document, found that an ontology graph without attached text answered 3–4 of 20 questions while the same graph with text chunks answered 18 of 20 ([ontology study](https://arxiv.org/html/2511.05991v1)). A hand-built typed graph with verbatim cards attached to nodes is exactly the supported form, with 100% entity coverage by construction. No head-to-head against curated graphs exists below 1,000 units, so this rests on indirect evidence.

| Option | Verdict for ~200 cards | Evidence |
|---|---|---|
| Graph-first scoping plus BM25 plus dense RRF | Keep | Already the recommended hybrid ([Wang et al.](https://arxiv.org/html/2407.01219)) |
| Deterministic contextual headers | Add, free | Anthropic's technique without LLM calls |
| Cross-encoder reranker | Test against gold card IDs | Benefit is ordering at this size; ~1 s per query |
| Compact catalog in the prompt (CAG) | A/B experiment only | Long context ties or beats RAG at ~32k tokens; loses on abstention ([LaRA](https://arxiv.org/html/2502.09977v1)) |
| GraphRAG, LightRAG, RAPTOR | No | 10–100x indexing cost, poor abstention, no lookup gain |
| HippoRAG 2 | Only if multi-hop evals fail | Best accuracy per token among graph methods |
| ColPali, VisRAG | No | ~258 KB per page; text plus reranker reached 63.6 vs 59.8 nDCG@10 for the best visual retriever ([ViDoRe V3](https://arxiv.org/html/2601.08620v1)) |
| Late chunking | No | Needs token-level embeddings a pooled embeddings endpoint does not return |

The long-context option deserves a real test because the corpus fits comfortably. LaRA finds long context ahead of RAG by 2.4 points at 32k tokens and behind by 3.7 at 128k, strongly ahead on comparison questions (+15 points, which matches "NIR versus Raman for this matrix") and behind on unanswerable questions (-10.4 points at 32k) ([LaRA](https://arxiv.org/html/2502.09977v1)). Abstention is a hard requirement here, so retrieval stays primary. If a catalog experiment is run, it should hold a compact card catalog (ID, claim, scope label, graph neighbors; ~10–20k tokens) with the question last, and the model should return card IDs only. The decisive unknown is TTFT at 20k, 40k and 60k tokens: the 0.12–0.16 s figures were measured on short prompts, no long-prompt number exists for these models, and the prefix cache is unreliable on this architecture. Six requests settle it.

For image-only slides, visual retrievers are the wrong tool at this size. ColPali reaches 81.3 nDCG@5 against roughly 66 for OCR pipelines ([ColPali](https://arxiv.org/html/2407.01449v6)), but newer evidence shows a text pipeline with a good reranker can match or beat visual retrieval, and VLMs localize evidence poorly (F1 0.09 versus 0.60 for humans) ([ViDoRe V3](https://arxiv.org/html/2601.08620v1)). The real risk is silent transcription error in wavelengths, concentrations and units: recognition errors cut RAG performance by nearly 50% in OHRBench ([OHRBench](https://arxiv.org/html/2412.02592)). The recommended path is two different VLMs transcribing each slide, a diff, human verification of every span that becomes a card, and a retained source crop for citation, with the card labeled "VLM-transcribed". Qwen3.5 is natively multimodal, and the one-time cost is two requests per slide, a rounding error against the monthly cap.

"Verbatim by construction" should replace "verbatim by instruction". Even the best systems in ALCE lacked complete citation support about half the time on open-ended questions ([ALCE](https://arxiv.org/html/2305.14627)), so the model should emit only card IDs, constrained by a grammar enum to the retrieved set, and code should attach the stored quote and page and confirm the quote occurs on the cited page after whitespace and hyphenation normalization. This makes fabricated citation IDs impossible states and quote fidelity a measurable guarantee rather than a hope.

## The engine owns the verdict and the LLM may only tighten it

Vendor guidance, measured costs and failure studies converge on a fixed workflow for a task with known stages. Anthropic advises predefined code paths when steps are knowable and notes that autonomy "raises costs and allows errors to compound" ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)); its own multi-agent system consumed ~15x the tokens of chat and is explicitly "not a good fit" for tightly dependent work ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Tool-agent consistency collapses on repeated trials (pass^8 below 25% on tau-bench ([tau-bench](https://arxiv.org/abs/2406.12045))), and the MAST taxonomy attributes most multi-agent failures to system design and inter-agent misalignment rather than model limits ([MAST](https://arxiv.org/html/2503.13657v3)). The assessment (extract, check, retrieve, compose, decide) is therefore a DAG: free-roaming ReAct, orchestrator-workers and a separate planner add tokens and run-to-run variance to a decision status that must be stable. Autonomy belongs only in follow-up chat, as a single agent with a handful of idempotent tools (read assessment state, explain a rule, retrieve cards, rerun the assessment with new facts and return a diff, list open questions) and a hard cap of three or four tool calls. A router that chooses between answering from state, retrieving once and rerunning the engine should route on tool need, not difficulty, and default to the grounded path, because Adaptive-RAG's classifier reached only 54.5% accuracy ([Adaptive-RAG](https://arxiv.org/pdf/2403.14403)).

The neuro-symbolic literature supports putting the symbolic component in the decision seat. LLM-Modulo argues that LLMs cannot plan or self-verify alone and should act as approximate knowledge sources inside a loop with external model-based critics ([Kambhampati et al.](https://proceedings.mlr.press/v235/kambhampati24a.html)), and an instance lifted GPT-4-Turbo success 4.6x on TravelPlanning ([Gundawar et al.](https://arxiv.org/abs/2405.20625)). LLM self-correction without external feedback does not reliably help ([Huang et al.](https://arxiv.org/abs/2310.01798)). The chemistry agents that work pair a general LLM with small deterministic tools and hard-coded stops: ChemCrow's controlled-substance match halts execution, and its authors found an LLM grader preferred fluent GPT-4 answers while expert chemists preferred the tool-grounded agent ([ChemCrow](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/)). The existing design, where the engine decides and the LLM can only make things stricter, is this pattern. It should be formalized as a monotone merge over an ordered status lattice (for example outside scope, then insufficient information, then provisional) plus an additive risk set, so that a property-based test can assert the final severity never falls below the engine's. That formalization is an inference, not a cited system. The evidence base itself is thin: planning benchmarks and workshop-scale ontology studies, with no quantified neuro-symbolic study in process analytics.

CRAG's relevance gate transfers with one change. A lightweight evaluator labels retrieved evidence as correct, ambiguous or incorrect (84.3% accuracy versus 58.0% for ChatGPT on PopQA) at about +0.15 s per generation ([CRAG](https://arxiv.org/pdf/2401.15884)), mapping onto supported, weakly supported and unsupported cards. CRAG's web-search fallback must become "mark as unsupported or ask", because an open-web fallback breaks the corpus-only contract. Verified web search should therefore be a separate, optional, off-by-default path that produces only claims of the class "external": fetch the page, record URL and access date, require a verbatim quote that passes the same string check against the fetched text, restrict to an allowlist of regulators, standards bodies and manufacturer datasheets, and run it asynchronously after the main report so it never blocks the 8–18 s path. This is a design inference; the notes found no benchmark of verified web search for technical advice, and the chemistry agents that use web search do so under expert review.

Clarification questions ranked by decision impact are best computed rather than generated. Bayesian experimental design is the principled frame (Uncertainty of Thoughts reports a 38.1% average task-success gain ([UoT](https://proceedings.neurips.cc/paper_files/paper/2024/hash/2b0e14abd8128e6bf98b6b0bec1cfcbf-Abstract.html)); BED-LLM and Kobalczyk et al. estimate expected information gain from LLM beliefs ([BED-LLM](https://arxiv.org/abs/2508.21184), [Kobalczyk et al.](https://arxiv.org/abs/2502.04485))), and asking at the right moment helps (up to 74% improvement in Ambig-SWE ([Ambig-SWE](https://arxiv.org/abs/2502.13069))). Here the engine is an exact simulator, so the LLM need not estimate anything: for each unknown slot, rerun the deterministic assessment over expert-set prior values and measure how much the decision status, ranked methods and probe concept change, weight by status-flip risk (a wrong provisional answer is asymmetrically costly) and divide by client effort, then cap at three to five questions and proceed provisionally with stated assumptions. Question wording should be authored per slot by experts and stored with the rules, which costs zero LLM tokens. Abstention must come from structure (a critical slot is unknown, a scope rule fails) because verbalized confidence is overconfident ([Know Your Limits](https://arxiv.org/html/2407.18418v3)). Whether the engine is fast enough to make hundreds of counterfactual runs cheap is unmeasured; the whole deterministic stage takes under 0.1 s, so it very likely is.

Expert-in-the-loop belongs at knowledge authoring, not per request: the LLM drafts candidate cards and rule patches, automated gates check schema, citation resolution and conflicts plus a golden-set regression, an expert approves, and the persisted version carries approver identity so assessments cite card versions. LangGraph-style interrupts are the documented mechanism for pausing at out-of-scope outcomes, engine-versus-LLM disagreement and knowledge-base changes ([LangGraph](https://docs.langchain.com/oss/python/langgraph/interrupts)). No quantitative study of approval gating's effect on error rates exists.

## Claim support needs a calibrated cascade, not a stricter critic

The 0.649 claim-support score cannot yet be read as a generation-quality number. It comes from one generic 31B critic for which the research found no grounding-benchmark score, probably scored with a binary supported/unsupported rubric (to be confirmed). Factuality metrics are biased against paraphrase and against evidence far from the point of use ([Godbole and Jia](https://arxiv.org/abs/2501.14883)), which describes "plain-language restatement of a quote" and "claim that synthesizes two cards"; NLI-style citation checks cannot represent partial support ([ALCE](https://arxiv.org/html/2305.14627)); and sentences that are assumptions, proposals or unknowns are not verifiable claims and should not be scored for quote support at all ([VeriScore](https://arxiv.org/pdf/2406.19276)). The first step is therefore measurement: an expert labels 150–300 real report sentences as supported, partially supported or unsupported with a claim type, double-labeling 30–50 for agreement, and the critic and two small checkers are scored against those labels. ARES-style prediction-powered inference needs about 150 labeled points to put a confidence interval on the support rate ([ARES](https://arxiv.org/html/2311.09476v2)). The need for intervals is concrete: with 20 evaluation cases a case-level rate such as plan_ok (0.842) carries a 95% interval of roughly plus or minus 15 points, and an expert, not an LLM judge, should grade factual quality, as ChemCrow's grader disagreement showed.

Small specialist checkers match large judges at a fraction of the cost. On the LLM-AggreFact leaderboard FactCG-DeBERTa-L (0.4B) scores 75.6 and MiniCheck-Flan-T5-L (0.8B, MIT licence) 75.0, against GPT-4o at 75.9, Qwen2.5-72B at 75.6 and Llama-3.3-70B at 74.5 ([leaderboard](https://llm-aggrefact.github.io/), [FactCG](https://arxiv.org/html/2501.17144)); checking 13K test pairs cost about $0.20 versus $107 for GPT-4 ([MiniCheck](https://arxiv.org/html/2404.10774v2)). Bespoke-MiniCheck-7B leads at 77.4 but is CC BY-NC, acceptable for a hackathon and not for a product ([model card](https://huggingface.co/bespokelabs/Bespoke-MiniCheck-7B)). The input (one sentence plus one to three short quotes) is the format these models were trained on, and since the checker runs locally it consumes no quota. Two caveats apply: no source publishes per-pair latency for short inputs (HHEM-2.1-open's 1.5 s per 2k-token input on CPU is the only datapoint ([HHEM](https://huggingface.co/vectara/hallucination_evaluation_model))), and none of these benchmarks contains process-analytics prose, so thresholds must be tuned on the project's own labels. The judge's weakness is fixable too: giving an LLM judge expert-labeled peer examples lifted balanced accuracy on a hard benchmark to 84.0 versus at most 68.8 for zero-shot prompts ([FaithJudge](https://arxiv.org/html/2505.04847v2)).

Numbers need their own guard placed before any neural model. A fine-tuned encoder reached only 36.5% accuracy on canonical-equivalent unit rewrites (95 C versus 368.15 K), rising to 98.2% after symbolic augmentation, though that is a single-author 2026 preprint ([arXiv 2607.16212](https://www.alphaxiv.org/abs/2607.16212)). The rule "no number may appear in a sentence unless it is in a cited quote, the engine output or the client input" should be unit-aware: parse value, unit and comparator tuples, normalize, tolerate rounding, treat derived values as valid only when marked as computed from named quantities, and hard-fail on mismatch without a model call. That converts the three invented numbers in the evaluation to a zero-by-construction property. It also extends to quantity roles (an upper bound turned into a point value, a range narrowed), which NLI models tend to accept.

When a sentence fails, patch it; do not regenerate. RARR preserved 78–85% of the original text versus 10–21% for competing editors on NQ, using an edit cap (rejecting edits over 50 characters or 0.5x the original) and an agreement check ([RARR](https://ar5iv.labs.arxiv.org/html/2210.08726)). In a 2026 comparison of claim-level repair, deletion removed the most unsupported content but kept only 64.3% of the text, rewriting kept 80.1% but removed the least unsupported content, and 83.5% of answers already judged clean were edited anyway ([repair study](https://arxiv.org/abs/2608.29307)), which is the over-editing a whole-report repair guarantees. A fourth action fits this schema better than either: relabel an unsupported sentence as an assumption, proposal or unknown with explicit hedging, which keeps the information and removes the false grounding implication. The action depends on claim type: a wrong number on a sourced fact is rewritten constrained to the cited quote; an unsupported claim is relabeled or deleted; a rewrite is never allowed to strengthen a claim. Every patch is re-verified by the same checker, capped at two iterations, then falls back to deletion or downgrade. The cascade therefore runs: structural policy and citation checks (milliseconds), unit-aware numeric guard, small checker over every verifiable sentence with a grey band instead of one 0.5 cut, an LLM judge with a three-level rubric and expert examples only for grey-band sentences (an estimated 10–25%), and parallel sentence patches. The routing figures are estimates, and the thresholds must come from the expert-labeled set. Streamed text should be labeled "drafting, unchecked" until promoted, so no unverified numeric claim ever appears as final.

## Regulatory logic and instrument physics supply what the model must not invent

The assistant occupies an apparently unoccupied niche, which warrants caution rather than a novelty claim. LLM work on spectroscopy targets structure elucidation and spectral prediction: a 2026 benchmark found general LLMs "lack precise spectral grounding", scoring functional-group F1 of 0.38–0.41 against far better 1D-CNNs ([SpecX](https://arxiv.org/abs/2605.18791)). The closest agent, LUMIR, handles few-shot regression and its results are self-reported ([LUMIR](https://arxiv.org/pdf/2507.21471)). Commercial tools such as Infometrix Ai-Metrix automate calibration-sample selection and factor counts rather than feasibility scoping ([Infometrix](https://infometrix.com/aimetrix/)), and ICH Q14 says machine-learning models "will not be discussed in detail" ([ICH Q14](https://database.ich.org/sites/default/files/ICH_Q14_Guideline_2023_1116.pdf)). The implication is architectural: the LLM never reads spectra or invents spectroscopic values, it plans, explains and calls deterministic tools. The one evaluation of LLMs for analytical-method tasks found that retrieval and guided reasoning help and that general models beat chemistry-specialized ones ([LLMs as Lab Engineers](https://preview.aclanthology.org/ingest-acl/2026.findings-acl.2015/)); its six-dimension rubric (specificity, correctness, usefulness, feasibility, misinformation risk, error handling) is a ready grading scheme for expert review of plans.

The feasibility plan should be a template with a defensible skeleton, filled by the engine and tailored by the LLM, which targets the plan_ok gap (0.842). No single feasibility standard exists, but the guidance converges: define an analytical target profile first, then risk-assess variability and interface, choose technique and probe geometry, collect data that deliberately spans every variability source, keep reference-method error well below the target, validate on independent batches, test robustness, and write a maintenance plan ([FDA NIR guidance](https://www.fda.gov/media/91343/download), [ICH Q14](https://database.ich.org/sites/default/files/ICH_Q14_Guideline_2023_1116.pdf), [ICH Q2(R2)](https://database.ich.org/sites/default/files/ICH_Q2%28R2%29_Guideline_2023_1130.pdf), [EMA NIR guideline](https://www.ema.europa.eu/en/documents/scientific-guideline/guideline-use-near-infrared-spectroscopy-pharmaceutical-industry-and-data-requirements-new-submissions-and-variations_en.pdf)). Go/no-go has no published rule, so it must be expressed as comparisons of client-supplied numbers: target accuracy against reference-method error against demonstrated RMSEP, RMSEP against RMSEC, and the EMA check that the calibration range be at least 10x SEP. Regulated release use versus process monitoring changes the evidence burden sharply (Q14 Annex B rates on-line NIR blending in development as low impact, and NIR content-uniformity or assay for release and Raman raw-material identity as high impact), so the GMP context is a mandatory clarification question. Sample-count rules attributed to ASTM E1655 ("6x the number of variables", "20 validation samples") are unverified secondary claims from a paywalled standard and must not be hard-coded.

The recurring traps map one-to-one onto clarification questions and mitigation experiments: water content (strong NIR and MIR absorption, an advantage for Raman) and fluorescence (a vendor reports roughly 10% of Raman-active materials fluoresce at 785 nm ([Metrohm](https://metrohm.com/bg_bg/discover/blog/20-21/the-evolution-of-handheld-785-nm-raman-spectroscopy--raman-extra.html))); fibre material and length; temperature and pressure at the probe; fouling, flow, solids and bubbles; particle size; and chance correlation between analytes, which a bioreactor NIR study exposed when a glutamine model failed to predict spiking ([PMC3980391](https://pmc.ncbi.nlm.nih.gov/articles/PMC3980391/)). Fibre facts must carry a "vendor typical" label: chalcogenide fibre transmits 1.1–6.5 µm at 0.2–0.3 dB/m with 31% Fresnel loss and tight bend radii ([Art Photonics](https://artphotonics.com/product/chalcogenide-mid-ir-fibers/)), polycrystalline fibre 3–17 µm ([Art Photonics](https://artphotonics.com/product/polycrystalline-infrared-fibers/)), but a single vendor page quotes both 0.2–0.3 and 0.2–0.4 dB/m for the same product, so the assistant should request the datasheet or loss curve before any budget is presented.

Everything computable should be a tested pure function. Raman shift and wavelength conversions flag, for example, that a 3,000 cm-1 shift at 785 nm lands at ~1,027 nm, beyond many silicon detectors (computed in the research notes); ATR penetration depth reproduces Specac's published table exactly (2.01 and 1.00 µm for diamond/ZnSe at 1,000 and 2,000 cm-1, 45 degrees, sample index 1.5) ([Specac](https://www.specac.com/en/news/resource/depth-of-penetration-for-atr-measurements)), giving ready unit tests; fibre loss is 10^(-(αL + connector)/10) with Fresnel loss 1-(1-R)^2, and window intersection (fibre, crystal, detector, analyte band, water band) returns pass, partial or fail with the limiting component. Analyte band positions must come from a curated, cited table rather than model memory. In the report UI, every number should carry one of four provenance classes (client-provided, quoted with page and date, computed by a named tool with inputs, or assistant judgment) with unknowns shown as unknowns, which mirrors ALCOA and Q14's documentation norms ([FDA data integrity](https://www.fda.gov/media/119267/download)). No usability study of spectroscopists' report preferences was found, so this is inference from regulatory documentation conventions and merits a short interview with the company's application scientists.

## The recommended pipeline spends five requests and under 20 seconds

Putting the sections together, the architecture is a fixed DAG with six stages, one optional asynchronous branch and one bounded chat agent. Request counts and times are estimates from the measured rates; none has been measured end to end.

| Stage | What runs | Requests | Time (estimate) |
|---|---|---|---|
| 0. Deterministic | Graph scoping, engine, card retrieval (RRF plus headers), status lattice, counterfactual question ranking, expert-authored question text; paints scaffold, headline status, evidence cards and ranked questions | 0 | <0.5 s |
| 1. Extraction | Typed slots with source spans via JSON schema, thinking off; confirmation echo table | 1 | 2.2–4.2 s |
| 2. Gate | CRAG-style supported/weak/none gate on cards per slot; "none" becomes unsupported or a question, never a web fallback | 0 | <1 s |
| 3. Drafting | Three parallel streamed section calls, shared report state, card-ID enums, evidence-before-conclusion fields, per-section token cap | 3 | 4.6–8.2 s |
| 4. Verification | Structural policy, unit-aware numeric guard, local small checker on every verifiable sentence, monotone-merge check | 0 | <1 s |
| 5. Grey band and patch | Verdict-only LLM judge on grey-band sentences, parallel constrained patches, re-verification, max two iterations, then delete or downgrade | 0–2 | 0–5 s |
| Optional | Verified web search (async, "external" claims only); chat agent with five tools and a three-to-four call cap | as needed | off the critical path |

That is 4–6 requests per assessment (typical 5), or about 600 reports per month at the 3,000 cap before development and evaluation use, against 750 at the current four calls. The pipeline also logs inputs, rule hits, retrieval scores, prompts and model versions for audit, and caches results by a hash of the canonical slots so repeated enquiries cost no requests.

Six measurements would replace most estimates and should precede large investments. A usage-counter check confirms thinking is off at every stage. A TTFT test at 20k, 40k and 60k tokens (with `cached_tokens` if exposed) decides the catalog experiment. A wall-time comparison of two-, three- and four-way splits against the call budget picks the split. A header comparison before and after a list-prompt `/completions` call settles quota semantics. An equivalence test of extraction on Qwen3-30B-A3B decides routing. And the 150–300-sentence expert label set, together with 50–100 enquiries with gold card IDs and expected "not covered" cases, calibrates the checker thresholds and measures recall@k, citation precision and recall, quote-match rate, refusal accuracy, monotonicity violations (must be zero), and repeat-run consistency in the pass^k style. Model and prompt versions should be pinned and the golden set rerun on every change.

## Conclusion

The central finding is that the research front for this problem is not where the hype is. Retrieval innovation (graph RAG, visual retrievers, rerankers, long-context caching) mostly addresses corpora orders of magnitude larger than this one, and several of its failure modes, notably weak abstention and silent entity loss, are worse for a system that must say "not in the corpus". The headroom lies in token economics and verification, and the first-hand data sharpen that: with sub-0.2 s first tokens, latency equals output tokens divided by decode speed, and a per-month request cap turns every LLM call into a scarce resource. That makes the cheapest-looking choices also the best ones. Deterministic sections written by code, expert-authored question text, a local grounding checker and sentence-level patching each cut seconds, tokens and requests at once, which is rare in an architecture trade-off.

The remaining uncertainty is concentrated in two places that no literature resolves. First, whether the 0.649 support score reflects bad drafting or a miscalibrated judge; a few hundred expert labels answer that and decide whether the generator needs any change at all. Second, whether the quality cost of parallel sections and smaller routed models is acceptable in this domain, which only the project's own gold set can show. If both come out well, decision status, citations and numbers become properties the code can guarantee (monotone, resolvable, unit-checked), leaving the LLM responsible only for readable prose, which is the only part of the assessment where its run-to-run variability is harmless.
