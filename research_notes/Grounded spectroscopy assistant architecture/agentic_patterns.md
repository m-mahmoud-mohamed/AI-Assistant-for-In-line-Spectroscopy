# Agentic and neuro-symbolic architecture patterns (2024-2026) for a grounded, cautious, explainable in-line spectroscopy advisory assistant

Research date: 2026-10-17. Evidence-quality tags used below: [paper] = numbers read from the full paper text; [abstract] = only the abstract/landing page was readable; [secondary] = search-engine summary or third-party write-up, not verified against the primary; [vendor] = vendor/engineering blog, unreviewed; [position] = position/opinion paper. Items from before 2024 are included only where they are the original source of a pattern that 2024-2026 work builds on, and are marked as such.

## 1. Fixed workflow (DAG / state machine) vs agentic RAG vs plan-and-execute vs ReAct: when does autonomy help and what does it cost?

### Takeaway
Vendor guidance (Anthropic, OpenAI, LangGraph) converges on: use predefined code paths wherever the steps are knowable, add LLM-driven autonomy only for open-ended sub-problems, and expect autonomy to cost tokens, latency and run-to-run consistency. Measured numbers point the same way: multi-agent runs cost ~15x the tokens of chat, tool-agent consistency collapses under repeated trials (tau-bench pass^8 < 25%), and most multi-agent failures are design/coordination failures rather than model limits. For an advisory pipeline whose steps are known (extract, check, retrieve, compose, decide) a fixed DAG is the better backbone; bounded autonomy fits only the follow-up chat.

### Cited Findings
- Anthropic defines workflows as "predefined code paths coordinate LLMs and tools" and agents as LLMs that "dynamically direct their own processes and tool usage"; it lists five workflow patterns (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) and says to start with the simplest solution, noting a single LLM call with retrieval is often enough [paper/guidance] — [Anthropic, Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (the fetched page did not display its date; I recall Dec 2024 but could not verify it here).
- Same source: workflows suit "well-defined tasks with predictable structure", agents suit open-ended problems where steps cannot be hardcoded; "agentic systems trade latency and cost for better task performance"; autonomy "raises costs and allows errors to compound"; prompt chaining "trades latency for accuracy on cleanly decomposable tasks"; agents should check ground truth from the environment at each step, include human checkpoints, and have stopping conditions such as a maximum iteration count — [Anthropic, Building effective agents](https://www.anthropic.com/engineering/building-effective-agents).
- Same source on tool design ("agent-computer interface"): tools need example usage, edge cases and clear boundaries; make mistakes harder to commit (they forced absolute file paths in their SWE-bench agent, after which the model used them reliably); frameworks can hide prompts and make debugging harder — [Anthropic, Building effective agents](https://www.anthropic.com/engineering/building-effective-agents).
- Anthropic's multi-agent research system (orchestrator-workers): agents use ~4x and multi-agent systems ~15x the tokens of chat; token usage alone explained ~80% of performance variance on BrowseComp; a Claude Opus 4 lead with Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on an internal research eval (eval size/scoring not described) [vendor] — [Anthropic, How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system).
- Same post, failure modes: early versions spawned "50 subagents for simple queries", searched endlessly for nonexistent sources, and errors compound (one failed step can send the agent down a different trajectory); agents are "non-deterministic between runs, even with identical prompts"; domains with shared context or many inter-agent dependencies are "not a good fit"; it only pays off for high-value tasks; production needed resumability, checkpoints/retry logic and rainbow deployments — [Anthropic, multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system).
- Same post, evaluation: one LLM-judge call with a rubric (factual accuracy, citation accuracy, completeness, source quality, tool efficiency) outputting 0.0-1.0 scores was most consistent; "human testing remained necessary to catch edge cases"; they recommend starting evals with ~20 queries — [Anthropic, multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system).
- OpenAI's practical guide (2025; date not shown in the extracted text): "maximize a single agent's capabilities first"; more agents add "complexity and overhead"; guardrails should be layered (LLM-based, rules-based such as regex/blocklists, output validation, tool risk ratings low/medium/high); plan human intervention with two triggers: exceeding failure thresholds and high-risk actions; guardrails can run concurrently with the main agent ("optimistic execution") — [OpenAI, A practical guide to building agents (PDF)](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf).
- LangGraph docs frame the same split: workflows "have predetermined code paths and are designed to operate in a certain order"; agents "define their own processes and tool usage"; the page lists prompt chaining, parallelization, routing, orchestrator-worker, evaluator-optimizer and does not discuss cost/latency trade-offs [docs] — [LangGraph, Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents).
- tau-bench (Sierra, June 2024): even gpt-4o-class function-calling agents succeed on "<50% of the tasks" and the proposed pass^k (success on all k trials) is "below 25%" at k=8 in retail [abstract] — [tau-bench, arXiv 2406.12045](https://arxiv.org/abs/2406.12045). Secondary summaries say Anthropic model cards now report pass^k [secondary] — [Sierra blog](https://sierra.ai/blog/tau-bench-shaping-development-evaluation-agents).
- MAST (Cemri et al., NeurIPS 2025): 14 failure modes in three categories (system design, inter-agent misalignment, task verification), built from 150 expert-annotated traces (kappa 0.88) and a 1,600+ trace dataset over 7 frameworks; authors conclude failures "primarily stem from system design issues and inter-agent misalignment", and that gains of multi-agent over single-agent systems are often minimal [paper, via search summaries] — [MAST, arXiv 2503.13657](https://arxiv.org/html/2503.13657v3).
- Plan-and-execute variant ReWOO (decouples planning from tool observations): reports ~5x token efficiency and ~4% accuracy gain on HotpotQA and robustness under tool failure [abstract; mechanism details not read] — [ReWOO, arXiv 2305.18323](https://arxiv.org/abs/2305.18323) (2023 origin).
- Agentic RAG survey (Singh et al., Jan 2025) defines agentic RAG as embedding agents in the RAG pipeline using four patterns (reflection, planning, tool use, multi-agent collaboration) and lists open challenges: evaluation, coordination, memory management, efficiency, governance [abstract] — [Agentic RAG survey, arXiv 2501.09136](https://arxiv.org/abs/2501.09136).
- Practitioner numbers for agentic vs static RAG cost (about 10x per query, several seconds extra latency; $0.041 vs $0.004 per query) are anecdotal and self-described as illustrative; I found no standardized benchmark reporting latency and cost side by side [vendor/blog, low quality] — see [budget-constrained agentic search, arXiv 2603.08877 (intro only read)](https://arxiv.org/pdf/2603.08877) and the blog roundup behind [this search](https://blckalpaca.at/en/knowledge-base/ai-agents/what-is-a-rag-system/agentic-rag-vs-klassisches-rag).
- Self-evaluation caveat that matters for "evaluator-optimizer" loops: LLMs "struggle to self-correct their responses without external feedback" and accuracy can drop after self-revision [abstract] — [Huang et al., arXiv 2310.01798](https://arxiv.org/abs/2310.01798) (ICLR 2024 per my recollection; venue not shown on the page).

### Inferences
- The assessment pipeline (requirements extraction -> physics/rule checks -> evidence retrieval -> composition -> decision status) has a known, ordered structure, which is exactly the "well-defined task with predictable structure" case where Anthropic/OpenAI/LangGraph guidance favours a workflow. A free-roaming ReAct loop here would add tokens, latency and non-determinism with no benefit, and would put the explicit decision status at the mercy of run-to-run variance (tau-bench pass^k, Anthropic's non-determinism note).
- Autonomy is justified only where the number of steps is genuinely unknowable: follow-up chat (the user may ask "what if the matrix changes", "why not Raman", "re-run with 30 m fibre") - and even there it should be a small bounded tool-use loop, not an open-ended planner. Single-agent-with-tools first (OpenAI) is the right default; multi-agent orchestration is not warranted because the task has shared context and tight dependencies (Anthropic's "not a good fit" case).
- Plan-and-execute (ReWOO-style) is attractive mainly for token efficiency in multi-hop retrieval; in this case the "plan" is already the fixed DAG, so the pattern is effectively subsumed.
- Because MAST attributes most failures to design and verification, the highest-leverage reliability investment is an explicit verification stage with symbolic checks, not a more capable planner.

### Gaps
- No peer-reviewed head-to-head of fixed pipeline vs ReAct vs plan-and-execute with latency and cost for an expert advisory task was found; the cost multiples are from vendor posts on research/coding tasks, not advisory pipelines.
- Anthropic's and OpenAI's pages did not display publication dates in the extracted text; dates (Dec 2024; Apr 2025) are from memory and unverified.
- The 90.2% multi-agent gain is an internal, undescribed eval (vendor claim).

## 2. Self-RAG, CRAG (Corrective RAG), Adaptive-RAG: mechanisms, reported gains, cost

### Takeaway
All three target retrieval quality and call-count adaptivity, with measurable gains on open-domain QA benchmarks, but none was evaluated on engineering advisory tasks. The transferable ideas are: (a) a cheap retrieval-quality gate with three-way action (use / discard-and-fallback / blend) from CRAG, which costs ~0.15 s extra generation time in their estimate; (b) a small complexity router that sends easy queries to cheap paths (Adaptive-RAG), cutting relative query time ~2.4x versus always-multi-step (3.60x vs 8.81x of single-step) at 1.9 F1 points lower (46.9 vs 48.9, FLAN-T5-XL); (c) Self-RAG's critique-and-cite behaviour, which requires a fine-tuned model and is therefore hard to adopt with hosted LLMs.

### Cited Findings
- Self-RAG (Asai et al., arXiv Oct 2023; ICLR 2024): trains one LM to decide when to retrieve and to emit "reflection tokens" critiquing retrieved passages and its own output, making the LM "controllable during the inference phase" [paper] — [Self-RAG abstract](https://arxiv.org/abs/2310.11511); ICLR 2024 venue confirmed in the reference list of [CRAG paper](https://arxiv.org/pdf/2401.15884).
- Self-RAG results (7B / 13B): PopQA 54.9 / 55.8 vs ChatGPT 29.3; PubHealth 72.4 / 74.5 vs ChatGPT 70.1; Biography FactScore 81.2 / 80.2 vs ChatGPT 71.8; ASQA citation precision 66.9 / 70.3 vs ChatGPT-with-retrieval 65.1 (citation recall 67.8 / 71.3 vs 76.6); ARC-Challenge 67.3 / 73.1 vs ChatGPT 75.3 (i.e. ChatGPT still wins on ARC) [paper] — [Self-RAG PDF](https://arxiv.org/pdf/2310.11511).
- Self-RAG practical properties: retrieval frequency is tunable at inference via a threshold on the reflection-token probability (less retrieval hurts PopQA more than PubHealth); a human check of 50 samples found the ISREL/ISSUP critique tokens "mostly aligned" with annotators; more supported citations but fluent outputs still contain claims not fully supported by citations [paper] — [Self-RAG PDF](https://arxiv.org/pdf/2310.11511).
- CRAG (Yan et al., Jan 2024): a lightweight retrieval evaluator (fine-tuned T5-large, 0.77B parameters) scores each retrieved document and triggers one of three actions: Correct (at least one document above upper threshold -> refine/decompose-then-recompose the documents), Incorrect (all below lower threshold -> discard and use web search), Ambiguous (intermediate -> use both) [paper] — [CRAG PDF](https://arxiv.org/pdf/2401.15884).
- CRAG results (SelfRAG-LLaMA2-7b base): CRAG vs standard RAG: PopQA +7.0 pts accuracy, Biography +14.9 FactScore, PubHealth +36.6, ARC +15.4; Self-CRAG vs Self-RAG: PopQA 61.8 vs 54.9 (+6.9), Biography 86.2 vs 81.2 (+5.0), PubHealth 74.8 vs 72.4 (+2.4), ARC 67.2 vs 67.3 (flat). With a plain LLaMA2-hf-7b base the reproduced Self-RAG collapsed (PubHealth 0.7), showing Self-RAG depends on its specially fine-tuned checkpoint [paper] — [CRAG PDF](https://arxiv.org/pdf/2401.15884).
- CRAG evaluator quality: on PopQA the T5 evaluator judged retrieval correctness with 84.3% accuracy vs 58.0% for ChatGPT (64.7% few-shot); ablations: removing the Correct action drops Self-CRAG PopQA accuracy 49.0 -> 43.6 (LLaMA2-hf-7b), removing refinement drops CRAG 54.9 -> 49.8 [paper] — [CRAG PDF](https://arxiv.org/pdf/2401.15884).
- CRAG cost (generation phase only, rough FLOPs estimate): execution time per instance RAG 0.363 s, CRAG 0.512 s, Self-RAG 0.741 s, Self-CRAG 0.908 s; TFLOPs/token RAG 26.5, CRAG 27.2, Self-RAG 26.5-132.4. Retrieval and data processing excluded. Stated limitation: fine-tuning an external evaluator is unavoidable [paper] — [CRAG PDF](https://arxiv.org/pdf/2401.15884).
- Adaptive-RAG (Jeong et al., NAACL 2024): a small LM classifier labels each query A (no retrieval), B (single-step), C (multi-step iterative); labels are auto-created from which strategy answered correctly plus dataset inductive bias [paper] — [Adaptive-RAG abstract](https://arxiv.org/abs/2403.14403), [PDF](https://arxiv.org/pdf/2403.14403).
- Adaptive-RAG results (FLAN-T5-XL, averaged over multi- and single-hop QA; time relative to single-step = 1.00): no retrieval F1 21.1; single-step F1 44.3 (1.00x); multi-step F1 48.9 (8.81x time, 4.69 steps); Adaptive-RAG F1 46.9 (3.60x time, 2.17 steps); with an oracle classifier F1 56.3 (2.11x time). With GPT-3.5: no retrieval F1 48.6, single-step 47.0, Adaptive 50.9 (1.46x), multi-step 50.9 (3.33x) [paper] — [Adaptive-RAG PDF](https://arxiv.org/pdf/2403.14403).
- Adaptive-RAG classifier: overall accuracy 54.5%; the classifier routed 8.6% of queries to A, 53.3% to B and 38.1% to C; absolute time per query 0.35 s / 3.08 s / 27.18 s; the authors note the labels may be noisy and the classifier is the main improvement avenue [paper] — [Adaptive-RAG PDF](https://arxiv.org/pdf/2403.14403).
- Caveat on benchmarks: all three are evaluated on open-domain QA / fact verification / biography generation (PopQA, TriviaQA, PubHealth, ARC, ASQA, HotpotQA etc.) over Wikipedia-style corpora, not on closed, curated, expert-authored knowledge with its own rules.

### Inferences
- CRAG's three-way gate maps well onto a curated corpus: "Correct" = evidence card supports the claim; "Ambiguous" = partially relevant, flag as weak support; "Incorrect" = no support. Replace CRAG's web-search fallback with "abstain / mark as insufficient evidence / ask the user", because an open-web fallback would break the corpus-only grounding contract. A cross-encoder or small LLM-judge can play the evaluator without fine-tuning a T5, but then the 84.3% evaluator accuracy is not guaranteed and must be measured on in-domain cards.
- Self-RAG's mechanism is not directly usable with hosted LLMs (needs training with reflection tokens); its useful behaviours (per-claim relevance/support/utility judgments, retrieve-on-demand) can be approximated as separate verifier calls, at the price of extra LLM calls and the self-evaluation unreliability documented elsewhere in these notes.
- Adaptive-RAG-style routing is most valuable in the chat agent: classify follow-ups as "answer from current assessment state" (no retrieval), "single retrieval from cards", or "rerun engine with new facts". Its measured behaviour (54.5% classifier accuracy; 3.6x time vs 1x for single-step) suggests keeping the router conservative and defaulting to the safer, grounded path when unsure; misrouting an engine-rerun query to "answer from state" would be a correctness risk, so route on tool-need rather than on difficulty alone (my design inference).
- Expect a retrieval-gate latency add-on on the order of 0.1-0.2 s per generation (CRAG's estimate) rather than a multiplicative cost, provided the gate is a small model and runs in parallel across slots.

### Gaps
- Per-benchmark numbers for CRAG/Adaptive-RAG on any technical/engineering corpus: none found.
- Self-RAG's own inference latency is only reported indirectly via CRAG's FLOPs estimate (range 26.5-132.4 TFLOPs/token); no wall-clock table in the Self-RAG paper text I read.
- No 2025-2026 follow-up replications comparing Self-RAG/CRAG/Adaptive-RAG on domain corpora were retrieved.

## 3. Neuro-symbolic designs: LLM + rule engine / knowledge graph / constraint solver; "LLM proposes, symbolic verifies"

### Takeaway
The strongest evidence for "LLM proposes, symbolic verifies" is from planning and logic benchmarks (LLM-Modulo: ~4.6x success for GPT-4-Turbo on TravelPlanning; Logic-LM: +18.4 pts over chain-of-thought) and from small ontology/rule-authoring studies where a formal reasoner catches defects the LLM cannot see. These designs put the symbolic component in the decision seat and confine the LLM to translation, drafting and explanation; that is the same role split the assistant already has (engine decides, LLM can only make stricter). Evidence in engineering/scientific advisory settings specifically is thin, mostly workshop-level.

### Cited Findings
- LLM-Modulo (Kambhampati et al., ICML 2024, PMLR 235:22895-22907) [position]: auto-regressive LLMs cannot by themselves plan or self-verify; the authors reject both "LLMs plan if prompted right" and "LLMs are only translators to external solvers", proposing LLMs as approximate knowledge sources inside a tight bi-directional loop with external model-based verifiers (critics), whose models can themselves be acquired with LLM help — [PMLR page](https://proceedings.mlr.press/v235/kambhampati24a.html), [arXiv 2402.01817](https://arxiv.org/abs/2402.01817).
- LLM-Modulo empirical instance (Gundawar et al., May 2024, TravelPlanning, 180 validation queries): GPT-3.5-Turbo baselines (CoT/ReAct/Reflexion) 0% / 0.6% / 0%; with LLM-Modulo 5%; GPT-4-Turbo improved 4.6x over baseline [abstract] — [arXiv 2405.20625](https://arxiv.org/abs/2405.20625). A follow-up extends it across four scheduling domains [secondary] — [arXiv 2411.14484](https://arxiv.org/html/2411.14484v1).
- Logic-LM (Pan et al.; EMNLP Findings 2023, pre-window origin): LLM translates the problem into symbolic form, a deterministic solver reasons, and solver error messages drive self-refinement; v2 reports +39.2% over standard prompting and +18.4% over chain-of-thought averaged on five logical-reasoning datasets (v1 on four datasets reported +62.6% / +23.5%, so quote the version) [secondary] — [Logic-LM, arXiv 2305.12295](https://arxiv.org/pdf/2305.12295).
- Ontology/rule generate-then-verify: a Siemens workshop paper has an LLM draft OWL 2 axioms for AI-system risk classification and a description-logic reasoner (HermiT) infer relevant hazards from a 63-category catalogue; reported full recall and zero false positives on two project profiles, and some LLM-authored defects were detectable only by the formal reasoner [workshop, small scale] — [LLMs4KGOE 3](https://ceur-ws.org/Vol-4246/llms4kgoe-3.pdf) (as summarised by search; I did not open the PDF).
- Another pattern: LLM fills ABox assertions and SWRL rules give the deterministic verdict, with an ablation showing the symbolic step adds value beyond structured prompting [under review, secondary] — [Semantic Web Journal submission](https://www.semantic-web-journal.net/content/structured-decomposition-llm-reasoning-cross-domain-validation-and-semantic-web-integration). OG-NSD feeds SHACL/OWL violations back to the LLM as corrective prompts in a repair loop [workshop, secondary] — [LLMs4KGOE 6](https://ceur-ws.org/Vol-4246/llms4kgoe-6.pdf).
- LLM-to-Prolog expert systems (Garrido-Merchan and Puente, arXiv Jul 2025, v2 Jan 2026): structured prompt-based extraction of knowledge from LLMs into Prolog so human experts can validate and correct it; claims "strong adherence to facts" with Claude Sonnet 3.7 and GPT-4.1 but no metrics are on the abstract page [abstract, preprint] — [arXiv 2507.13550](https://arxiv.org/abs/2507.13550).
- Systematic review of neuro-symbolic AI (Colelough and Regli, arXiv Jan 2025; 1,428 papers screened, 167 analysed, 2020-2024): research concentrates on learning/inference; explainability and meta-cognition received less attention [secondary summary] — [arXiv 2501.05435](https://arxiv.org/pdf/2501.05435v1).
- Guardrail framing from OpenAI: layer rules-based deterministic protections (regex, blocklists, limits) with LLM-based classifiers and output validation rather than relying on one — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf).
- LLM self-verification is unreliable: models struggle to self-correct without external feedback [abstract] — [Huang et al.](https://arxiv.org/abs/2310.01798); self-evaluation is unreliable but multi-LLM checking helps, per the abstention survey [paper] — [Know Your Limits, TACL 2025](https://arxiv.org/html/2407.18418v3).
- Evidence that LLM/ML calibration models struggle on extrapolation, relevant to the "calibration does not transfer to a new matrix" premise check: a 2026 benchmark of TabPFN vs PLS/Ridge/CatBoost/1D-CNN on 66 NIR datasets found the foundation model's advantage shrinks on spectral outliers and extrapolated samples, where classical chemometrics stays competitive [abstract, preprint] — [arXiv 2605.21544](https://arxiv.org/abs/2605.21544).

### Inferences
- The assistant's existing design (deterministic engine whose output the LLM may only make stricter) is the "LLM-Modulo" idea instantiated with a hand-written verifier; the literature supports keeping the verdict symbolic and using the LLM for extraction (free text -> typed slots), explanation and drafting new rules/cards for expert approval.
- "Stricter only" can be formalised as a monotone merge over an ordered status lattice (e.g. outside scope > insufficient information > provisional) and an additive risk set: the LLM may propose extra risks or a downgrade, never remove an engine-raised flag or upgrade a status. This is an inference, not a cited pattern, but it makes the guarantee testable by a property-based test (merge never decreases severity).
- Round-trip checks catch LLM extraction errors that a rule engine cannot: after the LLM extracts "fibre 50 m, 1550 nm", a deterministic validator should re-render the typed requirements to the user as a confirmation table (the Logic-LM / OG-NSD translate-then-validate-then-repair loop), because extraction errors propagate silently into engine inputs.
- Because the SWRL, OWL and Prolog examples are small studies or preprints, they support the pattern's plausibility, not a quantified benefit for spectroscopy advice.

### Gaps
- No quantified neuro-symbolic study in industrial process analytics or PAT advisory was found; the nearest are risk-classification (Siemens workshop) and planning benchmarks.
- Absolute success rates for LLM-Modulo on TravelPlanning were not retrievable (only the 4.6x ratio and the GPT-3.5 0 -> 5%).
- No evidence retrieved on knowledge-graph-backed LLM advisors for spectroscopy or analytical instrument selection specifically.

## 4. Tool-augmented scientific agents (ChemCrow, Coscientist, ChemAgents) and LLM work on spectroscopy / chemometrics / PAT

### Takeaway
Chemistry agents (ChemCrow, Coscientist, ChemAgents) pair a strong general LLM with narrow, deterministic domain tools (property/price/safety lookups, documentation search, code execution) and rely on hard-coded safety checks; their lessons are that agent quality is bounded by tool quality, LLM graders favour fluent answers over correct ones, and human/expert review stays necessary. LLM work specifically for spectroscopy/chemometrics is sparse and aimed at spectral prediction or structure elucidation, not at feasibility advice for in-line deployment; I found nothing on LLM-based probe/method selection for PAT.

### Cited Findings
- ChemCrow (Bran et al., Nature Machine Intelligence, 8 May 2024): GPT-4 with 18 expert-designed tools; demonstrated planning/execution of an insect repellent and three organocatalysts and guiding a chromophore discovery — [PMC11116106](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/), [EPFL summary](https://actu.epfl.ch/news/an-ai-leap-into-chemical-synthesis-2).
- ChemCrow tool categories (from the paper text; the fetch counted 19 listed, text says 18): general (WebSearch, LitSearch, Python REPL, Human = asks the user), molecule (Name2SMILES, SMILES2Price, Name2CAS, Similarity, ModifyMol, PatentCheck, FuncGroups, SMILES2Weight), safety (ControlledChemicalCheck, ExplosiveCheck, SafetySummary), reaction (NameRXN, ReactionPredict, ReactionPlanner, ReactionExecute); loop is ReAct-style Thought/Action/Action Input/Observation [paper] — [PMC11116106](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/).
- ChemCrow safety: hard-coded checks plus prompted guidelines; a controlled-substance match stops execution, a similarity above 0.35 triggers a warning; dangerous reactions halt execution [paper] — [PMC11116106](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/).
- ChemCrow evaluation: 14 tasks, four expert chemists vs an LLM grader (EvaluatorGPT); experts preferred ChemCrow on complex tasks needing grounded chemistry, GPT-4 alone did better on easy, memorised tasks (DEET, paracetamol), and EvaluatorGPT favoured GPT-4 because its answers looked more fluent/complete; authors conclude LLM-based evaluation cannot be trusted when factuality matters. Stated limitations: results depend on tool quality and inaccurate tool output misleads the agent; closed models limit reproducibility [paper] — [PMC11116106](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/).
- Coscientist (Boiko et al., Nature 624:570-578, 2023): GPT-4-driven system with internet and documentation search, code execution and lab-automation modules; documentation search improved accuracy with lab-automation APIs; six tasks including Pd-catalysed cross-coupling optimisation; supporting information probes misuse (hazardous chemicals) [secondary summaries of a primary paper; pre-2024 but foundational] — [Coscientist summary](https://www.chemistryviews.org/?p=76389), [PMC10733136](https://pmc.ncbi.nlm.nih.gov/articles/PMC10733136).
- ChemAgents (ChemRxiv, July 2024): hierarchical multi-agent robotic "AI chemist" on a local Llama-3-70B; a Task Manager delegates to four role agents, each with one shared resource; six experimental tasks; a Sept 2025 review cites it; peer-reviewed venue of the final version unconfirmed [preprint, secondary] — [ChemRxiv preprint](https://www.cambridge.org/engage/chemrxiv/article-details/66a8c11bc9c6a5c07a7a59c0), [Chem. Synth. review](https://www.oaepublish.com/articles/cs.2025.66).
- Review: Ramos, Collison and White, Chemical Science 2025 (first posted Dec 2024) describe agents as LLMs with tools; hallucination is intrinsic and sanity-checking tools only partly mitigate it; recommend human-in-the-loop checkpoints; challenges are data quality/integration, interpretability and lack of benchmarks [secondary summary] — [Chem. Sci. review](https://pubs.rsc.org/doi/d4sc03921a), [arXiv 2407.01603](https://arxiv.org/pdf/2407.01603).
- Verification gap survey (arXiv 2608.05179, labelled submitted 29 June 2026; the ID/date pair looks inconsistent, treat date as unverified): when a physical experiment closes the loop it does the verifying, but the model's explanation is not tested; of 24 runnable AI-scientist systems ~83% released code but only ~38% released seeds/traces; among nine closed-loop systems no LLM-era system used an externally validated oracle inside its loop [abstract, preprint] — [arXiv 2608.05179](https://arxiv.org/abs/2608.05179).
- LUMIR (Xie et al., arXiv Jul 2025, Sun Yat-sen University) is the closest LLM-agent-for-spectroscopy paper found: a pipeline with a structured literature knowledge base mined from peer-reviewed IR papers, automated preprocessing (AsLS baseline, Savitzky-Golay, SNV, MSC, detrending), feature extraction (PCA, PLS, CWT, NMF) and few-shot prompting for classification, regression and anomaly detection on Milk NIR, herbs, CRP, an industrial wastewater COD set, Tecator and Corn [paper] — [LUMIR, arXiv 2507.21471](https://arxiv.org/pdf/2507.21471).
- LUMIR numbers: entity extraction of the research object from 100 hand-written queries was 82% (qwen-turbo) and 86% (qwen-plus) with task-type accuracy 89% and 100%; LLM regression R2 on Corn 0.925 (best of baselines; PLSR 0.885), wastewater 0.919 (vs PLSR 0.745), but on Tecator the LLM (0.959) trailed PLSR (0.970), SVR (0.988) and CNN (0.980); the choice of backbone mattered enormously (Corn R2 0.925 with GPT-5-chat vs 0.812 qwen-plus vs 0.673 deepseek-v3; Milk classification 96.1% vs 69.7% vs 50.8%); prompt length near context limit can induce numeric hallucination [paper] — [LUMIR PDF](https://arxiv.org/pdf/2507.21471). This paper is a spectral-prediction agent, not a feasibility advisor; its few-shot gains are for small datasets (67-215 samples).
- SpectraLLM (ICLR 2026, arXiv 2508.08441): LLM for molecular structure elucidation from multi-spectral data (IR, UV-Vis, Raman); adding Raman corrected some IR/UV-Vis-only mispredictions (reported Raman Tanimoto similarity 0.25) [secondary] — [arXiv 2508.08441](https://arxiv.org/pdf/2508.08441).
- RamanBench (arXiv 2605.02003): 74 datasets, 325,668 spectra, 28 ML models; it benchmarks classical/deep ML, not LLMs or agents [abstract/secondary] — [arXiv 2605.02003](https://arxiv.org/abs/2605.02003).

### Inferences
- The domain tools exposed by successful chemistry agents are small, deterministic, read-only calculators/lookups (molecular weight, price, safety screen, literature QA, code execution) plus a "Human" tool for asking the user. The spectroscopy analogue is the existing engine: fibre transmission window check, optical-state-to-probe-geometry mapping, premise checks, evidence-scope checks, plus retrieval of evidence cards. Exposing them as individually callable, schema-typed tools gives the chat agent ChemCrow-style grounding without free-form physics from the LLM.
- ChemCrow's hard-coded safety layer with stop/warn thresholds is the nearest precedent for making "outside supported scope" and "insufficient information" non-overridable by the LLM.
- The expert-vs-LLM-grader disagreement means evaluation of this assistant must use expert-graded or deterministic checks (does the answer cite a card; does the status match the engine), not an LLM judge alone, for factual claims.
- LUMIR's backbone sensitivity (50.8% to 96.1% on one task) is a reason to pin and regression-test the model version for extraction and composition, and to keep numeric judgement in the engine.
- For the "calibration does not transfer" premise, the 2026 TabPFN-vs-chemometrics result supports treating extrapolation as a first-class flag rather than trusting any learned predictor.

### Gaps
- No 2024-2026 paper found on LLM-assisted PAT feasibility, probe design, instrument selection or in-line method recommendation; searches for "LLM process analytical technology", "LLM chemometrics NIR calibration" returned only adjacent work.
- Coscientist/ChemAgents details are from secondary summaries; per-task success rates were not retrieved.
- ChemCrow's evaluation sample is small (14 tasks, 4 experts); no confidence intervals.

## 5. Clarification-question generation and abstention: asking vs answering, value-of-information ranking, selective prediction

### Takeaway
LLMs rarely ask clarifying questions on their own and answer ambiguous inputs confidently (CLAM, Ambig-SWE); asking at the right time measurably improves outcomes (up to 74% in Ambig-SWE; 38.1% average task-success gain from UoT's information-gain planning). The principled way to rank questions is expected information gain (EIG) over the decision variable (Bayesian experimental design: Kobalczyk ICLR 2025, BED-LLM ICLR 2026, UoT NeurIPS 2024); abstention research warns that verbalised confidence is overconfident and self-evaluation unreliable, so abstain decisions should come from external, structural signals (missing critical slots, rule-engine outcomes, evidence coverage).

### Cited Findings
- CLAM (Kuhn, Gal, Farquhar; Dec 2022 preprint, ICML 2023 workshop; pre-window origin): current LMs "rarely ask users to clarify ambiguous questions and instead provide incorrect answers"; a few-shot-prompted ambiguity detector asks only when needed and clarification raises accuracy on ambiguous questions without hurting unambiguous ones; users were simulated by a model with privileged information [paper/abstract, secondary] — [CLAM, arXiv 2212.07769](https://arxiv.org/pdf/2212.07769).
- Ambig-SWE / "Interactive Agents to Overcome Ambiguity in Software Engineering" (Vijayvargiya et al., Feb 2025): models "struggle to distinguish between well-specified and underspecified instructions"; interaction with a user yields improvements of "up to 74%" over non-interactive settings; unwarranted assumptions risk poor outcomes and tool misuse [abstract] — [arXiv 2502.13069](https://arxiv.org/abs/2502.13069). A follow-up reports a 69.40% resolve rate from a scaffold that separates underspecification detection from execution [secondary, date unverified] — [arXiv 2603.26233](https://www.alphaxiv.org/abs/2603.26233v2).
- Uncertainty of Thoughts (Hu et al., NeurIPS 2024): simulates future question-answer branches, scores them with an information-gain-motivated uncertainty reward, propagates rewards to pick the question with maximum expected reward; on medical diagnosis, troubleshooting and 20 Questions the NeurIPS version reports a 38.1% average improvement in task success over direct prompting with fewer questions (an earlier workshop version reported 57.8%, so cite the peer-reviewed figure) [abstract/secondary] — [NeurIPS abstract](https://proceedings.neurips.cc/paper_files/paper/2024/hash/2b0e14abd8128e6bf98b6b0bec1cfcbf-Abstract.html).
- Active Task Disambiguation (Kobalczyk et al., ICLR 2025): formalises task ambiguity as a candidate-solution set larger than the true set and chooses clarifying questions by Bayesian-experimental-design information gain, outperforming approaches that reason only in question space; the authors argue effective question generation needs meta-cognitive reasoning LLMs "may presently lack" [abstract] — [arXiv 2502.04485](https://arxiv.org/abs/2502.04485).
- BED-LLM (Choudhury et al., arXiv Aug 2025; ICLR 2026): sequential Bayesian experimental design that builds a probabilistic model from the LLM's own predictive distributions to estimate EIG over a target variable at each turn; "substantial gains" over prompting-based design generation on 20 Questions and preference inference; success depends on model formulation, belief updating and EIG estimation strategy; no numbers on the abstract page [abstract] — [arXiv 2508.21184](https://arxiv.org/abs/2508.21184).
- Trained clarifier on tau-bench data using amortised BED and a user simulator (arXiv 2606.03135); only method sections seen [preprint, partial] — [arXiv 2606.03135](https://arxiv.org/pdf/2606.03135).
- Abstention survey (Wen et al., TACL 13:529-556, 2025): abstention is judged from three angles (query answerability, model confidence, human values); methods include query ambiguity detection, token-likelihood/entropy and verbalised confidence, sampling-consistency, few-shot "None of the above" prompting, self-evaluation and multi-LLM checks; findings: models are reluctant to express uncertainty even when wrong, verbalised confidence is overconfident, self-evaluation is unreliable (multi-LLM helps), abstention is sensitive to prompt wording; over-abstention is a real cost; recommended metrics are coverage, reliable accuracy, abstention precision/recall, accuracy-coverage and risk-coverage curves (AUACC, AURCC), abstain-ECE, and combining several because none suffices [paper] — [Know Your Limits](https://arxiv.org/html/2407.18418v3), [TACL record](https://aclanthology.org/2025.tacl-1.26).
- Confidence elicitation (Xiong et al., ICLR 2024): black-box verbalised confidence tends to be overconfident; consistency across samples and better aggregation help; white-box methods are better but the gap is small (AUROC 0.522 vs 0.605 in the cited comparison); no method consistently wins and all struggle on tasks needing professional knowledge [abstract/secondary] — [arXiv 2306.13063](https://arxiv.org/abs/2306.13063v2).
- OpenAI guide: escalate to a human after exceeding failure/retry thresholds or on high-risk actions — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf). tau-bench pass^k measures consistency over repeated trials — [tau-bench](https://arxiv.org/abs/2406.12045).

### Inferences
- Question ranking by decision impact can be done almost exactly with the existing engine, without an LLM estimating EIG: for each unknown requirement slot, enumerate plausible values from an expert-set prior (e.g. analyte concentration range, path length class, matrix phase, temperature/pressure band), run the deterministic assessment on each completion, and measure how much the distribution over (decision status, ranked methods, probe concept) changes. EIG = reduction in expected entropy (or expected change in recommended action) per slot, optionally divided by answer effort/difficulty for the client. This replaces BED-LLM's LLM-estimated belief updates with an exact simulator, which is cheaper, auditable and reproducible; the LLM is then used only to phrase the question and to detect ambiguity in free text. This is my design inference built on the BED literature, not a cited system.
- Key unknowns that flip the status (e.g. "is the target in the sample the analyte or the matrix", "does the calibration matrix match the process matrix") should be asked first even if their probability-weighted entropy is modest, because the cost of a wrong provisional recommendation is asymmetric; add a risk-weight to EIG (my inference).
- Abstention/decision status should be derived from structure, not from LLM self-confidence: "insufficient information" when any critical slot that changes the engine outcome is unknown; "outside supported scope" when an engine scope rule or evidence-scope check fails; "provisional" otherwise. Report coverage vs accuracy (per the survey's metrics) on a golden set to tune over-abstention.
- Asking should be capped (the top 3-5 ranked questions, then proceed provisionally with stated assumptions) to avoid over-asking; the literature supports asking only when ambiguity is detected (CLAM) and measures benefit in task success, not question count.

### Gaps
- No study ranking clarifying questions in a rule-/physics-engine-backed expert advisory setting was found; the BED work is on 20 Questions, preferences, medical diagnosis and coding.
- Numbers for BED-LLM and Kobalczyk et al. were not retrievable (abstract pages only). The UoT figure differs between versions (38.1% vs 57.8%).
- CLAM's benchmark numbers were not verified from the primary PDF.
- No published calibration data for how users answer technical clarification questions (e.g. clients not knowing their matrix composition); the "I don't know" answer handling is a design gap.

## 6. Human-in-the-loop expert review patterns (approve cards/rules, feedback loops)

### Takeaway
Current practice and tooling favour an LLM-proposes / programmatic-check / expert-approves / versioned-persist loop for rule and knowledge authoring, with explicit interrupt points and audit trails; production agent guidance adds escalation on failure thresholds and high-risk actions. Direct quantitative evidence of benefit for HITL review is mostly absent from the 2025-2026 sources found (mostly abstracts and preprints), but the ChemCrow expert-vs-LLM-grader disagreement is concrete evidence that expert assessment cannot be replaced by LLM judges for factual quality.

### Cited Findings
- LangGraph `interrupt()` pauses a graph mid-node, needs a checkpointer (durable DB-backed in production) and a `thread_id`, and resumes with `Command(resume=...)`; documented patterns are approve/reject, review-and-edit state, tool-call approval (with editable arguments) and input validation; the node re-executes from its start on resume, so side effects before `interrupt()` must be idempotent [docs] — [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts).
- OpenAI: human intervention is "especially important early in deployment", helps "identify failures, uncover edge cases, and establish a robust evaluation cycle"; two triggers (failure thresholds, high-risk actions); rate each tool low/medium/high risk by read/write access, reversibility and impact to trigger checks or escalation — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf).
- Agent Gym (arXiv 2608.15591, v1 16 Aug 2026, v2 14 Oct 2026): wraps an existing LLM agent in an evaluate-and-correct loop; subject-matter experts discover and validate correction rules through natural-language interaction; a "programmatic safety loop" checks rule correctness before human approval; hybrid deterministic-LLM correction engine; reference implementation on invoice processing; no quantitative results on the abstract page [abstract, preprint] — [arXiv 2608.15591](https://arxiv.org/abs/2608.15591). A search summary additionally describes schema/conflict checks and approval metadata with an audit log; I could not confirm those from the abstract [secondary].
- Garrido-Merchan and Puente: LLM-extracted Prolog knowledge bases are designed to be validated and corrected by human experts [abstract] — [arXiv 2507.13550](https://arxiv.org/abs/2507.13550).
- A community vision paper argues for pairing human expertise with automation in a continuous curation loop where LLMs formalise claims and humans resolve flagged inconsistencies [secondary] — [arXiv 2506.16596](https://arxiv.org/pdf/2506.16596). A simulated-oracle study stores oracle-provided rules as validated items and flags conflicts as outdated [secondary] — [arXiv 2507.17131](https://arxiv.org/pdf/2507.17131).
- ChemCrow: experts and an LLM grader disagreed (experts preferred the tool-augmented agent; the LLM grader preferred the fluent GPT-4 answers) and the authors conclude expert human assessment is needed for scientific tasks — [PMC11116106](https://pmc.ncbi.nlm.nih.gov/articles/PMC11116106/). Anthropic similarly found "human testing remained necessary" even with an LLM judge — [Anthropic multi-agent post](https://www.anthropic.com/engineering/multi-agent-research-system). The Chem. Sci. review recommends human-in-the-loop checkpoints — [Chem. Sci. review](https://pubs.rsc.org/doi/d4sc03921a).
- Verification-gap survey: closed-loop LLM-era systems seldom include an externally validated oracle; releasing execution traces is a recommended audit artifact (only ~38% did) — [arXiv 2608.05179](https://arxiv.org/abs/2608.05179).

### Inferences
- Treat expert-authored cards/rules as the source of truth and the LLM as a drafter of candidate cards and rule patches. Pipeline: LLM proposes -> automated gates (schema validity, citation resolves, no conflict with existing rules, regression run over a golden set of past enquiries with expected status) -> expert approval via an interrupt/review queue -> versioned persistence with approver identity, timestamp and rationale (audit log) -> the assessment output cites the card version. This follows Agent Gym's described structure but is my synthesis; Agent Gym itself lacks reported results.
- Feedback loop: every expert correction to an assessment (edited status, rejected recommendation, added risk) should become a candidate regression test and, if generalisable, a rule/card patch proposal. Use pass^k-style repeated runs on golden cases to catch regressions from model or prompt changes.
- At runtime, use interrupts for (a) out-of-scope or insufficient-information outcomes where a human expert could extend scope, (b) engine-vs-LLM disagreement, and (c) any proposed change to the knowledge base; do not interrupt for routine provisional assessments, to keep latency acceptable.

### Gaps
- No quantitative study found showing the effect of expert-approval gating on error rates in an LLM advisory system.
- Agent Gym and the verification-gap survey are very recent single preprints with abstract-level evidence only; Agent Gym's date metadata (v1 Aug 2026) and the survey's (June 2026 date vs 2608 ID) should be treated as unverified.
- Review-queue workload and expert time cost were not found in any source.

## 7. Recommended orchestration design (synthesis; items marked "inference" are not cited findings)

### Takeaway
Use a deterministic, checkpointed DAG (LangGraph-style) as the assessment backbone with LLM calls confined to typed extraction, claim-level evidence judging and constrained composition, a symbolic verifier gate before output, an engine-driven value-of-information ranking for clarification questions, and a bounded single-agent tool loop (with the engine and evidence retrieval as tools) for follow-ups. Add experts as approvers of cards/rules and as reviewers on defined interrupt triggers. This follows vendor guidance (simplest workable pattern, single agent first, layered guardrails, human triggers), and the neuro-symbolic evidence (symbolic verifier in the decision seat).

### Cited Findings
- Design principles this synthesis relies on, each documented above: start with the simplest solution and use workflows for predictable tasks — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents); maximise a single agent before adding more, layer deterministic and LLM guardrails, escalate on failure thresholds and high-risk actions — [OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf); keep verifiers external because LLMs cannot self-verify reliably — [LLM-Modulo](https://proceedings.mlr.press/v235/kambhampati24a.html), [Huang et al.](https://arxiv.org/abs/2310.01798); checkpointed pause/resume for human review — [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts); agent consistency should be measured with pass^k — [tau-bench](https://arxiv.org/abs/2406.12045); retrieval-quality gating adds modest cost — [CRAG](https://arxiv.org/pdf/2401.15884).

### Inferences
#### A. Proposed pipeline (assessment run)
1. Intake (LLM, structured output): parse free text into typed requirement slots with source-span provenance and per-slot status (stated / inferred / unknown). One call; temperature 0; JSON schema; deterministic post-validation (units, ranges, enumerations). Echo the typed requirements back to the client for confirmation (translate-then-validate loop).
2. Deterministic engine: fibre transmission windows, optical state -> probe geometry, premise checks, evidence-scope checks. Output: candidate methods, probe concepts, flags, a baseline decision status and the list of "decision-critical unknowns".
3. Clarification ranker (no LLM): VOI by counterfactual re-runs of the engine across the prior over unknown slots; select top-k unknowns by (decision impact x status-flip risk) / client effort. LLM only phrases questions in plain language. Cap at 3-5 questions; proceed provisionally with stated assumptions.
4. Evidence retrieval and gate (RAG, fixed routing): per claim/slot retrieve cards; CRAG-style three-way relevance/support gate (use / weak / none); "none" -> mark as unsupported or abstain, no open-web fallback. Run slots in parallel.
5. Composition (LLM, constrained): write the assessment (requirements, recommendation, risks, study plan) only from engine output + gated cards, with each statement tagged to a rule ID or card ID. The LLM may add risks or downgrade confidence but cannot remove engine flags or raise status.
6. Verifier gate (symbolic first): (a) monotonicity check: final status >= engine status in severity, risk set superset of engine's; (b) every claim carries a resolvable citation or a rule ID; (c) numbers in prose match engine numbers; (d) no recommended method outside the engine's candidate set unless flagged. Optional single LLM-judge/NLI pass for claim-support only, treated as advisory because LLM self-evaluation is unreliable. On failure: one bounded repair attempt, then fall back to a templated engine-only report.
7. Output with decision status; log full trace (inputs, rule hits, retrieval scores, prompts, model version) for audit and expert review.

#### B. Chat agent (follow-ups and re-run)
- Single agent with a small, well-documented tool set (Anthropic's ACI advice; OpenAI's tool risk rating): `get_assessment_state`, `explain_rule(id)`, `retrieve_cards(query)`, `rerun_assessment(new_facts)` (idempotent, returns diff of status/risks/recommendation vs previous run), `list_open_questions`. All tools are read-only or idempotent, so risk is low.
- Adaptive-RAG-style router (small model or rules) deciding: answer from current state, single retrieval, or engine re-run; default to the grounded path when uncertain. Hard step cap (e.g. 3-4 tool calls), then answer or escalate.
- Every chat answer passes the same verifier gate; the agent cannot state a status that did not come from the engine.
- Re-run semantics: new client facts update typed slots with provenance; the re-run shows what changed and why (explainability), and conflicting facts trigger a clarification instead of silently overwriting.

#### C. Cost and latency expectations (my estimates, not measured)
- LLM calls per assessment: ~3-5 (intake 1; optional question phrasing 1; per-slot evidence gate batched or small-model; composition 1-2; optional claim-support judge 1); engine and VOI are CPU-only and cheap. Independent steps parallelise, so wall-clock is roughly intake + max(retrieval, engine) + composition + verifier. This is far below the 4x to 15x token multiples reported for agent/multi-agent systems (Anthropic) and within CRAG's ~0.15 s gate overhead per generation.
- Chat turn: 1 routing decision + 0-3 tool calls + 1 answer; ~2-4 LLM calls.
- Caching: cache engine results by canonical slot hash, cache embeddings and card evidence judgments per (claim, card version).

#### D. Where each reviewed pattern is and is not used
- Fixed DAG: backbone (yes). Prompt chaining + parallelisation + routing: yes. Orchestrator-workers / multi-agent: no (shared context, tight dependencies). Plan-and-execute: no separate planner (plan = DAG). ReAct: only inside the bounded chat agent. Self-RAG: no (needs fine-tuned model); its per-claim support/utility critique is approximated by the evidence gate. CRAG: gate yes, web fallback no. Adaptive-RAG: router in chat, not in the assessment. LLM-Modulo / Logic-LM style: engine as verifier, verifier gate as critic; repair loop capped. BED/UoT: replaced by exact engine-based VOI. HITL: approval of cards/rules, interrupts on defined triggers.

#### E. Evaluation plan (needed to justify the design)
- Golden set of enquiries with expert-labelled status, ranked questions and required risks; report status accuracy, over-abstention vs under-abstention (coverage/accuracy curves), citation-support rate, monotonicity violations (must be 0), and pass^k consistency over repeated runs (tau-bench style). Use expert grading for factual quality; keep LLM judges for style and rubric checks only (ChemCrow's grader/expert disagreement).
- Pin model versions and run the golden set on every prompt or model change (LUMIR's backbone sensitivity).

#### F. Main failure modes to design against
- Extraction errors silently feeding the engine (mitigate: schema validation, confirmation echo, per-slot provenance). Over-asking or under-asking (cap, VOI weighting). Evidence gate misjudging relevance (measure evaluator accuracy on in-domain cards; CRAG's 84.3% was on PopQA). Router misclassification in chat (conservative default). LLM prose contradicting engine numbers (numeric consistency check). Silent drift from model updates (golden-set regression). Compounding errors in loops (step caps, deterministic fallbacks, checkpoints/resumability as in Anthropic's production notes).

### Gaps
- None of the cited sources evaluates this exact combination (physics/rule engine + RAG + clarification ranking + chat re-run) on an expert advisory task; the design is assembled from patterns validated in other settings, so its aggregate latency, cost and accuracy must be measured.
- Optimal values for question caps, step caps and abstention thresholds are not available from the literature and need calibration on the project's golden set.
- Prior distributions over unknown slots for the VOI calculation have to come from domain experts; no source gives them.
